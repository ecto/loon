# Agent-First Design

Most Loon code will not be typed by a person. It will be generated by a
model, checked by a harness, reviewed by a person — maybe — and run. This
document makes that assumption explicit and turns it into a design lens:
when a language decision is close, decide for the agent.

This is not a lowering of standards. Agents are the harshest usability
audience a language has ever had: they write code faster than any human,
they never read the manual, and they arrive with strong priors absorbed
from every other language. A quirk a human would learn once and route
around, an agent will re-trip over in every fresh context window, forever.
Designing for agents is designing for ruthless, high-volume, prior-laden
users — which turns out to produce a language that is better for humans
too.

Sibling documents: [capabilities.md](capabilities.md) and
[record-replay.md](record-replay.md) describe two capabilities this lens
values highly; this document explains *why* they matter more than they
first appear to.

## The three failure modes

An agent interacting with a language fails in exactly three ways:

1. **Prior mismatch.** The model writes what would be correct in Python,
   Clojure, or Rust, and Loon silently does something else. The agent has
   no way to notice — the code parses, runs, and returns a value. This is
   the worst failure mode and the one this document exists to eliminate.
2. **Feedback starvation.** The agent makes a mistake and the diagnostic
   doesn't say enough to fix it. Humans open a browser; agents retry with
   a guess. Every diagnostic that fails to teach costs a round-trip.
3. **Unverifiable output.** The agent produces code and cannot check its
   own work — no oracle, no reproducer, no way to know if the fix fixed.

Each failure mode implies a principle.

## Principle 1: Priors are part of the spec

For an agent, the "intuitive" behavior of a construct is whatever the
training distribution says it is. Loon is a bracket lisp, so the dominant
prior is Clojure's; for `match`, `Option`, and `?` it is Rust's; for
general scripting patterns it is Python's.

Where the prior is good, match it exactly. Truthiness is the canonical
example: Loon's rule — only `false`, `()`, and `None` are falsy; `0`,
`""`, and empty collections are values and therefore truthy — is
Clojure's rule with `None` playing `nil`. An agent that never reads a page
of Loon documentation will guess it correctly. `if-let` binds the payload
of a `Some`, which is Rust's `if let` semantics under a Clojure surface —
both priors agree, so the form does what every model expects.

Where the prior is bad (Python's `0` and `""` falsiness is a defect
factory), diverge — but *loudly*, at the exact point of divergence. That
is Principle 2's job.

The one-sentence forms matter. Rules that fit in a sentence survive
context compression; rules that need a table do not. Loon's truthiness
rule is: **a value is truthy unless it says no (`false`) or says nothing
(`()`, `None`).**

## Principle 2: The error message is the documentation

Agents do not read docs; they read diagnostics. Every Loon diagnostic
carries a `what`/`why`/`fix` triple, and `loon explain E0403` expands any
code into a tutorial. This is not a convenience feature — it is the
primary channel by which the language teaches its author.

The discipline this implies for language evolution: **every semantic
ruling ships with the diagnostic that teaches it at the moment of
confusion.** A rule that exists only in DESIGN.md does not exist for an
agent. When we ruled that unknown effect ops are hard errors instead of
silent `()`, the value was not the ruling — it was that the error names
the op and the handler stack that failed to catch it. When a condition's
inferred type can never be falsy, the checker should say so *and state
the falsy set in the fix text*, converting a latent prior mismatch into a
taught rule, in the loop, at zero cost.

A corollary: silent wrong behavior is the maximally expensive outcome and
is never an acceptable trade for speed or convenience. An agent generates
five hundred lines a minute. Every silent divergence is multiplied by
that rate.

## Principle 3: The language must be an oracle for its own output

An agent's real superpower is iteration speed — but iteration requires a
verifier. Loon is unusually well positioned here, mostly as a consequence
of one design decision: *all nondeterminism flows through effects.* The
payoffs compound:

- **Record/replay** (`loon run --record` / `loon replay`) means a crash
  is not a report, it is a *reproducer*. The agent-native loop this
  enables: run until crash with `--record`, write a fix, `loon replay`
  the tape against the fixed program, and know — not believe — the crash
  is gone. No other mainstream language offers this loop without heavy
  external tooling.
- **Handlers are free mocks.** A program that performs `Net.get` needs no
  mocking framework to test; wrap it in a test handler. Agents write
  correct tests when the test seam is a language construct rather than a
  library convention.
- **Capability grants** ([capabilities.md](capabilities.md)) mean
  agent-written dependencies can be *run without being trusted*. A
  generated package that was never granted `Net` cannot phone home, and
  `loon audit --capabilities` makes the claim checkable in CI. This is
  the missing precondition for an ecosystem where most packages are
  machine-written.
- **The conformance suite** treats the EIR VM as the semantic oracle and
  fails on any backend divergence — so "what does this program do?" has
  one answer, and an agent's mental simulation only has to be right once.

The roadmap items in this lens: attach a replay tape to every uncaught
runtime error automatically (a crash should *arrive* with its
reproducer); structured diagnostic output (`loon check --json`) so
harnesses stop parsing pretty-printers; and `loon test --json` for the
same reason.

## The prior-alignment corpus

Principle 1 is testable, and we test it. The prior-alignment corpus
(`crates/loon-cli/tests/prior_alignment.rs`) is a suite of programs an
agent would *plausibly write* — Python-shaped, Clojure-shaped,
Rust-shaped translations of common patterns. Each entry must do one of
two things:

1. behave the way the surface reading suggests, or
2. fail with a diagnostic that teaches the relevant rule.

The third outcome — running and silently doing something the surface
reading does not suggest — fails the suite. "Is Loon intuitive for
agents?" is thereby a failing test rather than a vibe. When a new
construct lands, its plausible misreadings go in the corpus; when a model
is observed making a novel Loon mistake in the wild, that transcript
becomes a corpus entry the way a production bug becomes a regression
test.

## The ruling checklist

Every future semantic ruling goes through this list before it merges:

- [ ] **Prior survey.** What do Clojure, Rust, and Python do here? If we
      diverge from a strong prior, why is the prior wrong?
- [ ] **One-sentence rule.** Can the semantics be stated in a sentence?
      If not, the design is probably wrong.
- [ ] **Teaching diagnostic.** Which error or warning fires at the point
      of likely confusion, and does its fix text state the rule?
- [ ] **Idiom.** What is the *blessed way* to use the feature, and does
      it exist in the language (macro, builtin, form) rather than only in
      documentation?
- [ ] **Conformance entry.** All backends agree, enforced by the suite;
      divergences pinned as expect-fail with reasons, never silent.
- [ ] **Prior-alignment entries.** The plausible misreadings are in the
      corpus.
- [ ] **Docs.** DESIGN.md states the rule; `loon explain` covers any new
      code.

## What this lens is not

It is not "make Loon look like Python." Where priors conflict with the
language's core commitments — effects over ambient authority, values over
nil, explicit absence over falsy sentinels — the commitments win, and the
divergence gets a loud diagnostic and a corpus entry. The lens governs
*how* we diverge (never silently), not *whether* we may.

It is also not hostile to humans. Every mechanism above — teaching
errors, one-sentence rules, free mocks, crash reproducers, one obvious
idiom — is exactly what a human newcomer wants too. Agents just remove
the option of pretending papercuts don't matter, because they hit every
papercut, at scale, forever.
